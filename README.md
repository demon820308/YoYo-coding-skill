# YoYo-coding-skill

面向个人开发者的通用软件工程治理 Skill，支持新建、接管、二次开发、重构、维护和迁移。

> **补强版 v1.3（2026-11-04）**：在 v1.0 基础上做四处整合，不改变原有六模式与工作流结构——①五条实证铁律（禁补丁、单一事实源、权威哈希、原子写、界面对账）已提升到 `SKILL.md` §2.1，为 MUST 并以抗压措辞书写；②四份 references 已定引用优先级（`SKILL.md` §3.1），冲突按序裁定；③第四份 reference 为《软件工程规范（通用复用版）·增强版》（[实证] 20 条原文＋[补入] 11 条，含安全与隐私、并发、迁移版本化、幂等、可观测性与发布恢复，及规则等级与例外管理总则）；④新增平台规则文件桥接规则（`SKILL.md` §9.1）：`AGENT_RULES.md` 为唯一事实源，平台只认 `AGENTS.md`/`CLAUDE.md` 时只放指针＋铁律摘要，不复制全文。原「最小必要变更」已澄清为「范围最小，落点正确」，与禁补丁不再冲突。另附 `USAGE.md` 使用说明（给人看）。

## 安装

将整个 `YoYo-coding-skill` 目录放入所使用 Agent 平台支持的 Skill 目录，并按平台规则启用。平台目录和加载方式可能不同，请以当前平台文档为准。

## 使用

在项目中提出任务，例如：
- “用工程治理流程初始化这个新项目。”
- “先接管并评估这个旧项目，不要改业务代码。”
- “按二次开发流程增加导出功能。”
- “评估这个模块是否值得重构，先给方案。”
- “定位并修复这个 Bug，保留现有未提交修改。”
- “制定从 SQLite 迁移到 PostgreSQL 的分阶段计划。”

Agent 应先读取 `SKILL.md`，再按需读取工作流、评估方法和模板。

> 使用者（人）先看 `USAGE.md`：两种启用方式、四个使用时机、六模式查表与可直接复制的派活句式都在那里。`USAGE.md` 是给人看的说明书，不代替 `SKILL.md` 作为 Agent 的规则本体。

## 设计约定

- 单 Agent 优先；专项 Agent 仅按需使用。
- 项目风险高于项目规模。
- 小任务轻流程，复杂或高风险任务增加计划和确认。
- 先理解存量项目，再修改。
- 不覆盖用户已有修改。
- 测试与交付必须基于真实证据。
- 五条铁律是正确性底线，不因项目小、任务急而豁免；比例原则只调节流程重量。
- Skill 不是权限沙箱；强制控制需由平台权限、Git、CI、备份等机制实现。

## 目录

- `core/`：核心判断、风险、变更和质量门禁（含铁律门禁）
- `workflows/`：六种项目工作流
- `assessment/`：存量项目评估方法
- `templates/`：项目与任务模板
- `checklists/`：关键阶段检查清单（含铁律逐条核对项）
- `references/`：四份规范原文，作为详细规则来源

## 规范来源与整合原则

本 Skill 的详细标准来源有四份，引用优先级见 `SKILL.md` §3.1，要点如下：

1. **本 Skill 的 SKILL.md**（最高）：尤其 §2.1 五条铁律。
2. **软件工程规范（通用复用版）·增强版**：真实项目整改提炼的 [实证] 20 条（每条带事故与验收）＋按体系补入的 11 条；更具体、更可验的标准以它为准。
3. **通用软件工程规范 V2.0**：工程基线全集，增强版 [补入] 条的来源；增强版未展开的更细条款以它备查，但其稀释措辞不覆盖增强版（见增强版文末对照说明）。
4. **AI Agent 通用工程治理规范 V1.0**：Agent 角色、权限、生命周期与审计。
5. **现代软件工程与 AI Agent 研发治理体系 V1.0**：仅用于立项定项目级治理强度（P0–P4）；任务级风险另用 SKILL.md 的 R0–R3，两套不混用、不换算。

本 Skill 只抽取个人开发场景所需的治理流程与执行入口，不替代原规范的完整条款。发生具体技术标准问题时，按上述优先级查阅 `references/` 原文，并结合项目技术栈适配。
