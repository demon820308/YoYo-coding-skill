# 质量门禁

## 最小门禁

任何代码变更：
- 修改范围与任务一致。
- 无意外覆盖用户改动。
- 至少执行与变更相关的验证；无法执行时说明原因。
- 检查实际 Diff。
- 报告未完成项和风险。

## 铁律门禁（MUST，任何风险等级均适用）

以下五项对应 `SKILL.md` §2.1，逐条核对，任一不过即不得宣称验收完成，例外须按 §3 例外管理留字：

1. **接缝检查（禁补丁）**：通读被改文件，能指出哪一段是后贴的、或新旧两套逻辑同时可达——不合格，整批按完整逻辑单元重写，不许只删被指出的那段。
2. **事实源检查**：本次涉及的跨模块决策（路径、判定、权限、状态、配置口径），计算点只剩事实源一处；显示层与行为层引用同一来源，没有「算出来只供显示」。
3. **哈希检查**：新增/修改的下载、导入、复用跳过逻辑，上游有哈希的必须验哈希；同尺寸篡改样本须被识别并自愈，或有对应用例证明。
4. **原子写检查**：新增/修改的用户状态写入路径统一走原子写工具（临时文件＋原子替换），无裸覆盖写。
5. **对账检查**：新增/修改的界面镜像状态有对账机制（回前台/切页刷新、失效修剪并提示、动作前验存在）；手工验证含「应用外增删 → 回到应用」正反场景，或注明本次不涉及镜像状态。

不涉及某条时，在交付报告中逐条写明「不涉及＋理由」，不许静默跳过。

## 按风险增强

R0/R1：
- 相关测试或运行验证
- Diff 检查

R2：
- 影响分析
- 相关单元/集成/回归测试
- 兼容性检查
- 回滚或恢复说明

R3：
- 用户明确授权
- 备份与恢复演练/验证（适用时）
- 分阶段执行
- 数据一致性与安全检查
- 发布后验证与停止条件

## 测试证据等级

- E0：未验证。
- E1：静态检查/代码审查。
- E2：局部命令或单元测试。
- E3：集成测试/构建/启动验证。
- E4：端到端或关键业务流程验证。
- E5：生产级观测、灰度或恢复验证（仅在适用且获授权时）。

不要为了追求高等级而执行不必要或有风险的测试。说明本次实际达到的等级及覆盖范围。结论用哪一级证据就标哪一级，不许以低等级证据冒充高等级结论（增强版第 20 条）。
