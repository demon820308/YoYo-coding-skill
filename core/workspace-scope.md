# 工作区范围与安装边界

## 1. 目标

YoYo 仅在安装它的当前项目工作区生效。项目 A 的 Skill、项目规则和项目状态不得自动成为项目 B 的规则。

## 2. 允许的项目级发现目录

按 Agent 平台选择**当前仓库根目录**下的平台项目级 Skill 目录：

| 平台 | 项目级目录 | Skill 入口 |
|---|---|---|
| Claude Code | `.claude/skills/yoyo/` | `.claude/skills/yoyo/SKILL.md` |
| Codex | `.agents/skills/yoyo/` | `.agents/skills/yoyo/SKILL.md` |
| 其他平台 | 仅使用经官方文档确认的项目级目录 | 不确定时先询问，不猜测 |

不得安装到用户级或系统级位置。具体平台说明见 `install/`。

## 3. 工作区根目录

1. 优先识别用户明确指定的项目根目录。
2. 若未指定，检查 Git 根目录、项目清单文件和 Agent 当前工作目录。
3. Monorepo 中，只有当用户确认 YoYo 适用于整个仓库时，才安装在仓库根目录；仅适用于子项目时，应使用该平台支持的子目录项目级发现位置，并验证实际发现行为。
4. 不得因为当前终端位于子目录，就把项目 Skill 安装到用户级或系统级目录。

## 4. 安装/升级前检查

- 检查目标目录是否已有 YoYo。
- 检查版本、文件清单和用户本地修改。
- 若已有版本，先比较差异并备份；不得直接覆盖用户修改。
- 同一工作区避免同时安装多个同名 YoYo Skill。
- 仅复制 Skill 文件；项目运行数据、密钥、缓存和用户资料不得打包进 Skill。

## 5. 项目状态与 Skill 分离

- Skill 本体位于平台的项目级 Skill 目录。
- 项目状态位于仓库根目录 `.yoyo/`。
- Skill 升级不得覆盖 `.yoyo/`。
- 项目档案升级时保留历史决策、验收报告和例外记录；只迁移字段，不重写历史事实。

## 6. 不等于安全沙箱

项目级安装限制的是 Skill 的加载/适用范围。它不会自动限制 Agent 访问仓库外文件、运行命令或访问网络。需要真正的工作区隔离时，必须同时配置 Agent 平台的 sandbox、权限或容器边界。
