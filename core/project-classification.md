# 项目识别与模式选择

## 识别顺序

1. 用户目标：新建、接管、增加功能、保持行为重构、修故障、迁移。
2. 仓库现状：空目录、已有代码、已有用户数据、生产运行状态。
3. 主要变更对象：业务行为、内部结构、运行平台、数据存储或故障点。
4. 确定主模式，可附加次模式。
5. 明确当前任务阶段，不把“项目整体状态”与“本次任务类型”混为一谈。

## 六种模式边界

| 模式 | 外部行为是否允许变化 | 核心关注 |
|---|---|---|
| NEW_PROJECT | 按需求定义 | 需求、架构、最小可用基线 |
| PROJECT_TAKEOVER | 不主动改变 | 理解、盘点、建立基线 |
| SECONDARY_DEVELOPMENT | 允许按需求变化 | 影响分析、兼容、回归 |
| REFACTORING | 原则上不变 | 行为保持、结构改善 |
| MAINTENANCE | 仅按修复目标变化 | 复现、根因、回归 |
| MIGRATION | 目标是兼容或经批准变化 | 数据/接口/运行一致性 |

## 组合示例

- “先接管，再增加支付方式”：主模式 TAKEOVER，后续任务 SECONDARY_DEVELOPMENT。
- “拆分模块并新增接口”：主模式 REFACTORING，次模式 SECONDARY_DEVELOPMENT。
- “修复 Bug，同时升级运行时”：主模式 MAINTENANCE，次模式 MIGRATION。

不要为了一个任务创建六套计划。按变更顺序拆阶段即可。
