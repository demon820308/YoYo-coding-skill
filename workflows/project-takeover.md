# PROJECT_TAKEOVER｜现有项目接管

## 入口

已有仓库，需要先理解、评估、建立基线或为后续任务做准备。默认只读。

## 步骤

1. 确认仓库/工作区根目录、项目目标和评估范围。
2. 检查 Git 分支、工作区状态、未提交修改和近期变更。
3. 阅读 README、平台规则、`.yoyo/` 档案（若存在）、配置、依赖清单和构建脚本。
4. 梳理目录、模块职责、关键调用链、数据流和外部接口；不凭目录名推断架构。
5. 探测安装、构建、测试、启动和部署方式；可执行时记录实际结果。
6. 检查数据库、迁移、环境变量和密钥管理；不得打印敏感值。
7. 评估测试、错误处理、日志、安全边界和技术债。
8. 将发现分为：阻断问题、当前任务相关、潜在风险、可延期技术债；标注证据和未知项。
9. 评估项目启动规范、三端规范、UI 规范的适用性；只读评估不要求立即全面采纳或重定版。
10. 形成项目画像和接管报告，等待用户选择下一阶段。

## 退出条件

项目结构、技术栈、运行/验证基线、Git 状态、关键业务路径、风险、未知项和建议行动均有记录。未执行的命令明确标注未执行。

## 禁止

评估阶段未经授权改业务代码、格式化、升级依赖、重建目录或追溯性补造历史决策。

## 后续路由

接管完成后按用户选择进入 SECONDARY_DEVELOPMENT、REFACTORING、MAINTENANCE 或 MIGRATION；保留接管报告，不重新做无差别盘点。
