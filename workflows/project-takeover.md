# PROJECT_TAKEOVER：现有项目接管工作流

## 默认策略

只读检查优先。除非用户明确要求修复，否则评估阶段不改业务代码、不做格式化、不升级依赖。

## 步骤

1. 识别仓库根目录、语言、框架、包管理器和主要入口。
2. 检查 Git 分支、工作区状态、未提交修改、最近提交。
3. 阅读 README、项目规则、配置文件、依赖清单和构建脚本。
4. 梳理目录、模块职责、关键调用链、数据流和外部接口。
5. 找到运行、构建、测试、部署方式；实际可执行时验证。
6. 检查数据库、迁移、环境变量、密钥管理方式；不得打印敏感值。
7. 评估测试覆盖、错误处理、日志、可观测性和安全边界。
8. 区分：
   - 阻断运行/开发的问题
   - 当前任务相关问题
   - 潜在风险
   - 可延期技术债
9. 形成评估报告，列出证据、未知项和建议优先级。
10. 等待用户选择后续开发、重构或维护方向。

## 评估报告至少包含

- 项目摘要与技术栈
- 目录/模块概览
- 启动、构建、测试命令及结果
- 核心业务路径
- 数据与外部依赖
- Git/工作区状态
- 已知问题与技术债
- 安全与运行风险
- 未确认事项
- 建议的近期行动（按优先级）

## 禁止

- 仅凭目录名推断架构。
- 把未运行的命令写成成功。
- 把所有旧代码问题都列为必须重写。
- 未经授权执行批量修复。
