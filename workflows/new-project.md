# NEW_PROJECT｜新项目建设

## 入口

从需求开始建设的新仓库/空目录。若目录已有代码或用户数据，先确认是否真为新项目；否则转 TAKEOVER。

## 目标与步骤

1. 明确产品目标、用户、核心场景、非目标、约束和验收标准。
2. 区分确定需求、假设和待确认项；识别数据、隐私、安全、部署和维护约束。
3. 依据需求选择技术栈，记录关键取舍，不为追新增加复杂度。
4. 读取项目启动规范，定版适用的架构分层、依赖方向、职责地图、目录结构、文件角色/增长阈值、全局事实源和质量护栏。
5. 若为 Windows/macOS/Linux 桌面跨端项目，按三端规范定版平台抽象、平台差异和构建矩阵；涉及 UI 时按 UI 规范确定界面结构和设计方向。
6. 建立仓库、依赖锁定、环境配置、格式化/Lint、测试和启动说明。
7. 先实现最小可运行垂直切片，再按需求扩展。
8. 建立 `.yoyo/` 项目档案；仅记录已确认事实，未知项标记 unknown。
9. 执行适用构建、测试、启动和验收，交付结果。

## 退出条件

- 需求边界和非目标明确。
- 项目骨架与适用规范采纳情况有记录。
- 最小工程基线可运行，验证命令可复现。
- 未完成项和后续风险明确。

## 禁止

未经确认堆砌复杂架构；无理由提前拆微服务/引入多 Agent；提交真实密钥；骨架未定版就持续堆业务代码。
